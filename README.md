# Connecticut Commuter in Cro-Magnon's Cave

*Formerly "Hands and Knowledge". Game records (the replay JSON) still carry `"game": "hands-and-knowledge"` as their format identifier, so records saved before the rename keep loading.*

A prototype survival-and-invention game. You wake with nothing but your hands and modern knowledge of how things work, in a procedurally generated prehistoric landscape whose plants, animals, stones and water you must learn by noticing, testing and trying. Hidden properties stay hidden; the character perceives them through noisy observation, field tests and outcomes.

This bundle contains the game source, the headless world generator and analysis tools, and the automated tests used during development.

## Setup

Requires Node 18 or later. Python 3 with Pillow is only needed for the landscape renders.

    npm install          # esbuild (bundler) and jsdom (headless browser for UI tests)
    npm run build        # writes dist/commuter-cave.html, a single self-contained page

Open `dist/commuter-cave.html` in any modern browser to play. Nothing else is needed: all code is inlined, and fonts load from Google Fonts with system fallbacks.

## For language models working on this project

Tests come in three tiers (see *Run times* below). **While iterating, run `npm run test:quick` (about 20 s).** Run the full `npm test` (about 1 min) once, after the last change and before reporting. Run `npm run test:soak` (several minutes) only when asked, or when a change reaches across the whole game flow (save/replay, the action set, travel, the start screen). Don't rerun a tier that passed unless code changed since. Prefer one combined change and one test run over several partial ones when a request has several parts.

Every build, simulation batch and test run reports its own run time. **In each response, report the totals for every build, simulation batch and test run you performed in that turn**, for example: "Build 0.6 s · test:sim 20.3 s · test:ui 1 min 29 s · test:smoke 4 min 36 s; all passed." Name any batch you chose not to run, and any step that failed. Use the npm scripts, which time themselves, or wrap ad-hoc commands in `tools/timed.mjs` so their time is reported the same way. Times depend on the machine; the point is to see what each change costs and to notice when something gets slow.

## Usage patterns

### 1. The game

`npm run build`, then open the page. Every module in `src/` is pure ES modules with no Node dependencies, so the same code runs in the browser and headless. `src/game.js` is the entry point; `build.mjs` bundles it with esbuild and inlines the result into `src/shell.html`.

### 2. Headless generation and simulation (`src/cli.js`)

    node src/cli.js generate --seed pig-rock --preset temperate-woodland --out out
        # out/world-pig-rock/: world.json (everything), report.md (game-master view),
        # long.csv (tidy source table), minerals.csv / plants.csv / animals.csv (wide views)
    node src/cli.js stats --n 300 [--preset ...]
        # starter-need coverage, toxicity, lookalikes, trait correlations, name diversity,
        # process reachability, biome mix, across many seeds
    node src/cli.js patch --seed pig-rock --entity P3 --n 6
        # lazy, deterministic patch samples of one archetype's varying traits
    node src/cli.js walk --seed pig-rock [--skill 0.9] [--n 12]
        # a scripted walk through microhabitats, printing field notes (pre-geography notes engine)
    node src/cli.js network --seed pig-rock --out out
        # out/world-pig-rock/network.md: process table, hubs and depth, reachability, goal trees
    node src/cli.js goal --seed pig-rock --goal fire
        # one goal tree with this world's candidate materials, and the character's thoughts
    node src/cli.js craft --seed pig-rock
        # bare hands to fire, narrated, for novice and expert characters with best and worst wood

Presets: `temperate-woodland`, `warm-savanna`, `cool-forest`, `dry-scrub`. Omit for a random climate.

In code:

    import { generateWorld, samplePatch } from './src/generator.js';
    import { generateLandscape } from './src/landscape.js';
    const world = generateWorld('pig-rock', { preset: 'temperate-woodland' });
    const L = generateLandscape(world);

Same seed and same code version always produce the same world. Every subsystem draws from a named random substream, so changing one part doesn't reshuffle the others.

### 3. Printouts and renders

- `report.md` and the CSVs from `generate` (game-master view of a world).
- `network.md` from `network` (the process network applied to a world).
- `npm run landscapes`: `tools/dump-landscapes.mjs` writes `out/lands.json` for four worlds, then `tools/render-landscapes.py` draws `out/landscape-<seed>.png` (shaded relief, vegetation, streams, lakes, hills, waterfalls, springs, spawn, 1 km scale bar). The player never sees these; they are for judging the generator.

## Code structure, file by file (`src/`)

### Foundations

**`rng.js`** — `makeRng(seed)` returns a seeded generator (mulberry32 over an FNV-1a hash) with `uniform`, `int`, `normal`, `logNormal`, `chance`, `pick`, `weighted`, `shuffle`, and `fork(label)`, which makes an independent named substream. Also `clamp` and `round`.

**`pack.js`** — Generated data to text and back (`pack`, `unpack`), keeping what JSON loses: grids (typed arrays, as base64), NaN and ±Infinity, keys holding undefined, and things reachable two ways. For keeping made worlds between test runs (`checkWorld`'s store in game.js).

**`act.js`** — The common shape of every process, and the machinery to run one. A process is a record naming the state it reads and the state it may change, as paths (`body.hyd`, `here.water`, `core.props`), with its time and effort (`hours`, `kcal`), an optional `ready` check, and a `run(v, dice)`. The view `v` is a copy of exactly the declared paths, nested the same way; `run` changes the copy and returns what it made (new things), used up (things, by uid), says (journal lines) and reports (anything else worth showing, such as what was counted). What it did is the difference between the copy before and after (`diff`): leaf changes (`{ path, from, to }`), additions to lists and sets (`{ path, added, removed }`), and a grid (typed array) changed as a whole. `rehearse` runs a process on a view without touching anything; `apply` brings each written path that changed into line with the run's copy. Copies keep shared things shared (a fix both in a stream's list and in a stretch walked along it is one thing in the copy), and applying keeps the state's own objects, updated in place, wherever the copy came from them, so whatever else holds them still holds them; things the run made are added new. Reading or changing a path that isn't declared throws, so a process can't reach past its contract. `world.…` and `L.…` are the generated world and land, constant through play, handed over without copying. A path written `+log` is append-only: the view starts it empty, and what's added is appended. Live keys (caches, counters for redrawing, what the screen shows, the dice as `rng`) read and write straight through at the top of the view. Dice come as `act` (this attempt's luck) and `place(key)` (chance fixed by where: the same key, the same draws). `stateOver` builds a state from namespaces, derived values and a base object. Because a run sees only its view and its dice, the same view can be run again with other dice: the basis for showing the spread of a process's outcomes.

**`acts.js`** — The game's processes in that shape: drinking, washing hands, making a bed, building a hut, feeding a fire, knapping, the other crafts (`CRAFTS`: notching a hearth board, touching up a notch, carving and trimming spindles, digging sticks and hardening them, cooking basins, washing and scorching things, tinder, bone splinters), one go at the hand drill (`DRILL_ATTEMPT`, with the reasons to stop as its `ready`), lighting a fire from an ember (`EMBER`), the germ mixing of everything handled in a job (`HANDLE`), resting (`REST`), the eight food preparations (`PREPARE(id)`), eating, what lives at a site (`POPULATION`, from the place's dice) and surveying it, an hour asleep (`SLEEP_HOUR`), and the per-tick processes (`TICKS`: sky and moon lines, metabolism, healing, warming, clothes, germs, drying, the fire in rain, illness coming on). Also the words for counts of things, germ mixing (`mix`) and bone finds. Nothing here touches the game; game.js binds the state and runs them (`perform`).

### World generation (species, stone, water)

**`environment.js`** — Level 1 of the generative graph. `generateEnvironment` samples latent drivers (temperature, precipitation, seasonality, bedrock, relief) and derives water balance, fire frequency, tree cover, biome name, lean season, and a catalogue of microhabitats with frequencies. `STONES` and `BEDROCKS` tables decide which stones exist; `generateStones` makes deposits (local bedrock, plus exotic cobbles carried in by streams) with hidden fracture, flaw, hardness and spall properties, visible cues, field-test results, deliberate-test results, uses, patch-varying traits and resemblance names. `generateClay` and `generateWater` make clay and water sources with hidden plasticity and pathogen load. `PRESETS` holds the named climates.

**`life.js`** — Levels 2 and 3. Plants: `plantArchetype` samples latent traits conditioned on the environment (growth pace, defense chemistry and strength, fibre, wood density, resin, bark, fruit, storage organs), using tables that encode apparency theory, the growth–defense trade-off and optimal defense theory (`DEFENSE_WEIGHTS`, `FRUIT_WEIGHTS`, `POTENCY`, `ALLOC`, `COOK`, `LEACH`). `plantParts` derives parts with collection tools, seasons, food safety (raw, cooked, leached, as ranges when defense varies by patch), nutrition and uses. `plantCues`, `plantFieldTests` and `plantDeliberate` derive what can be seen, tested quickly and tested deliberately. `makeLookalike` creates one deadly mimic of a safe herb. Fungi, mosses and lichens (`fungusArchetype`, `buildFungus`) share the plant interface: two to four mushrooms (gilled, with most harmless, some upsetting and about one in eight deadly with delayed symptoms and a mild taste, sometimes showing a ring and cup; brackets on dead wood that may be tinder fungus; puffballs), one or two mosses (cushion or bog) and one or two lichens (beard lichen, fine tinder; leafy ground lichen, famine food after leaching). About 40% of gilled mushrooms are cryptic, living under logs and in the litter. Animals: `ANIMALS` templates (invertebrates, small vertebrates, large animals, songbirds, soaring birds; invertebrates now include earthworms, woodlice, crickets and, in warm climates, termites, plus flying insects (flies nearly always, mosquitoes and gnats near water, bees and wasps where warm enough); a rare musk animal (skunk-like) has a smell; grubs, beetles, snails, worms, woodlice, crickets and crayfish are cryptic, found only by poking around; grubs and ants are nearly always present, often a second ant, plus four to six other kinds), `SIGN_PROFILE` (tracks with allometric length, calls from a small grammar via `makeCall`, scat, damage, dens, hair, speed, group size), `animalArchetype`, `buildAnimal` (density by Damuth-style scaling, catchability, food safety, field and deliberate tests). `pickVarying` chooses each archetype's patch-varying traits from `PLANT_VARYING` and `ANIMAL_VARYING`. `starterCheck` reports early-game needs and where to meet them.

**`variation.js`** — Patch-level variation. Each varying trait is a latent normal driven by shared site factors (moisture, fertility, exposure), a species-specific lineage factor, and noise, then transformed (logistic or exponential). `makeVarying` builds a trait from a catalogue spec with an integration level and lineage share (which set correlation strength). `siteFactors` and `sampleVarying` compute a patch's values as a pure function of seed, site and entity, so nothing is stored and discovery order never matters. `summarize` runs Monte Carlo over an archetype's habitats for means, spreads, correlations and per-microhabitat means.

**`names.js`** — Resemblance naming. `TABLE` maps visible-trait keys to familiar names (plum, cherry, peach for stonefruit; oak for acorn trees; and so on); `makeNamer` draws without replacement within a world; only when a name would collide does it gain a word for how this one looks (fruit colour, bark, tall or short, leaf texture, colour or size for animals: "red peach", "tall grass", "big ant"). Most animal kinds have one familiar name, and when a world has two species of one kind (two ants) both get their look ("red ant", "black ant"). In the journal the resemblance is the naming (`namingSentences` in notes.js): "peach-looking", "birch-like", "reminds me of a raspberry" mean the thing goes by that name from then on; hyphenated forms are used only for one-word names, and no comparison is made when the plain description already names it ("a red ant"). A made-up name (a collision word, an ordinal, or a descriptive name such as ironstone) is announced, not compared: "Some rusty, heavy blocks. I'll call it ironstone." Several new kinds of one sort found together are bundled: "A couple of different kinds of ant. I'll call them red ant and black ant." A new kind of something named here or at the previous place is "another", compared with the earlier one (bigger, smaller, its colour, its fruit, its leaves). Landmarks and places are not named this way: they're called what they are (see *names for places and landmarks*). A lookalike deliberately shares its model's name.

**`generator.js`** — Entry point for world generation. `generateWorld(seed, opts)` runs environment, stones, clay, water, plants and animals and attaches the starter check. `samplePatch(world, entityId, siteKey, microId)` gives one patch's varying traits.

### Geography

**`landscape.js`** — A 10 km square on a 128 × 128 grid (about 78 m cells). Elevation from layered value noise, short ridged relief scaled by ruggedness, a regional tilt, and escarpment steps. Priority-flood depression filling, with only large, deep basins kept as lakes; where water leaving a lake runs back into a lake on the same water level (within half a metre: another lobe of the same sheet of water, or a neighbour it brims over into), the shallow neck between is filled as lake too, so no stream runs out of a lake and straight back in. Over twelve seeds this adds 16% to lake area and joins 117 lakes into 82. Steepest-descent routing and flow accumulation give streams (brook, stream, river) at a catchment threshold set by the water balance. Topographic wetness index, vegetation density, features (hills by prominence, escarpments, waterfalls and cascades, spring heads, lakes; a run of adjacent steep channel cells is one feature at its steepest cell, and only a single-cell drop over 20 m counts as falls), and a microhabitat for every cell. `microShares` summarizes cover.

**`geo.js`** — Perceiving and moving through the landscape. `sightline` (line of sight over terrain, canopy attenuation by Beer–Lambert), `landmarks` (visual features and sound sources, with rough audible ranges), `lookoutScore` / `isLookout` / `lookoutEye` (open high ground; on forested hills the character climbs a tree), `hear` (the acoustic panorama: received intensity (R/d)² summed into 10° azimuth bins, separately for water noise and bird calls, blurred by about 15° so sources closer than about 30° fuse, peaks above threshold become percepts named after their dominant source; water within 120 m raises the threshold for everything else by 6 dB), `perceive` (sight plus `hear`, with vegetation, time of day and an optional boost for deliberate scanning), `loudWords` (sounds are reported by loudness, not distance), `suspicionFrom` (a noisy bearing and distance estimate), `waterKeyAt` / `waterKeyOf` (which body of water a cell or landmark belongs to: lakes, stream-and-river systems, and brooks), `lineHours` (the character's guess at walking time along a straight line, from the land along it), `stepHours` (Tobler's hiking function slowed by vegetation), `walk` (steps toward a believed target with accumulating heading error, smaller when walking between known landmarks; each step (`WALK_STEP`, a process in act.js's shape, run by `stepOnce`) is scored half by heading and half by walking distance to the aim over dry ground (`goalField`, Dijkstra in a window around the trip, the whole map if needed), with a little jitter and a penalty for cells already trodden, so the walker works round lakes instead of shuttling in a bay; an aim on a lake ends at its shore, re-sensing, lake avoidance and water stops; the trip keeps where each step began, and `stepView` rebuilds a step's view so it can be run again with other dice), `followWater` (downstream, or up the largest feeder, including from a lake shore), and `chooseSpawn` (the survivability criterion: a lookout findable from the spawn, from which water is visible; falls back to spawning within a kilometre of water).

**`mentalmap.js`** — The character's map as a graph. `trailGraph` (the links between visited places, from experience rather than geometry: walked trails first, then guessed shortcuts, under one greedy-spanner rule — a link goes down only where the map's best route between its two places is more than 1.5 times the link's own guessed time — and a link that would cross one already down is used only if nothing else joins its places), `firstClear` (which preferred place a landmark or a stretch of unexplored ground can hang off without its link crossing the map), `suspectedCrossings` (where a link cuts a stream as drawn), `shortestFrom` / `shortestPath` (Dijkstra over walking times; all routes from one node at once), `timeWords` / `awayWords` (walking times in words: plain when walked, "~" when guessed, "?" when only heard), and `explainTrip` (when a walk takes over 35% or 15 minutes longer or shorter than expected, the likeliest reason: farther or closer than it looked, drifting off line, thick brush, climbing, water in the way, open ground, downhill).

**`food.js`** — Food as chemistry. `COMPOUNDS` (tannin, cyanogen, lectin, oxalate, alkaloid, latex, saponin, stinging hairs, resin, aromatic, sulfur, lichen acids, mushroom toxins, amatoxin, shellfish biotoxin, parasites): how much thorough leaching removes, how much cooking destroys (wet heat only for lectins and oxalate needles, which roasting barely touches), how much escapes once crushed, potency, effect and taste or smell. `PART_SPECS`: for each kind of food part (nut, seed, grain, pod, storage organ, root, fruit, leaf, stem, flower, inner bark, small creatures, fatty grubs, shellfish, mushroom, lichen, honey) ranges for water, starch, sugar, fat, protein and fibre, the share of each absorbable raw, half an hour's yield, and extra compounds as chance-and-dose entries (rare properties are low chances). `sampleComposition` draws a part's make-up once per species; the plant's own defence becomes a compound at the strength of the old single toxin number. `expose` applies any exposure (`cut`, `crush`, `grind`, `heat` roast or boil, `water` still or running at a temperature, `dry`) to any make-up, under conditions from the gear and setting (`crushPower` from the pounding stone's hardness and weight, `rough` from the grinding stone's grit, `heatPower` from the fire or the number of hot stones); leaching roughly doubles per 10 °C; cutting makes smaller pieces without breaking cells, so it speeds leaching and cooking but frees little locked fat; crushing frees fat and protein and speeds leaching; heat gelatinises starch and kills parasites; volatile poisons escape once crushed and then dried, heated or soaked. `nutrients` digests: 4 kcal/g for starch, sugar and protein and 9 for fat, times what is absorbable, less tannin binding; digestion costs about a quarter of protein's energy, 7% of carbohydrate's, 2% of fat's, plus fibre. `tasteWords`, `smellWords`, `textureWords` are what the senses report from the current state, and `describeState` is the exact view. Numbers are first drafts to tune against `tests/sim/food-prep.mjs`.

**`sky.js`** — The world's clock: calendar, sun, moon, light, weather and temperature, all pure functions of the world (seed and climate) and the time, so the weather at a given hour is the same however the days before were spent, and a replay sees the same sky. `calendar`: a latitude implied by the climate (64 − 2.2 × mean °C + 10 × (seasonality − 0.5), 3° to 62°), a start day of the year from the seed (late March to mid-August), a seeded moon phase, and the annual swing of the daily mean temperature (wider far from the equator and in seasonal climates). `seasonOf`: winter, spring, summer, autumn; in monsoon climates (those whose lean season is a dry season) the wet and dry seasons. `sunAltitude`, `dayLength`, `dawnAt` (civil dawn, the sun 6° below the horizon; solar time, northern hemisphere) from the standard declination formula. `moonAt`: phase over 29.53 days, illuminated fraction, and altitude (it runs phase × 24 h behind the sun, its declination opposite the sun's at full). `weatherAt`: three-hourly, driven by a slowly wandering front (an AR(1) series with a memory of about two days), raining for a share of the time set by the year's rainfall and the season; thunderstorms on warm afternoons; snow below freezing; fog in the small hours and early morning, likelier after rain or fog, in wet country. `temperature`: the annual cycle (coldest mid-January) plus a daily one (coldest before dawn, warmest mid-afternoon), damped by cloud and rain. `skyAt`: illuminance in lux (sun, twilight, moon by the cube of its lit fraction, starlight, cut by cloud, the moon and stars more than the sun), visibility through the air (60 km clear, 4 km in rain, 250 m in fog), what rain leaves of hearing, and whether it's wet or dark. `seeingFar` (shapes against the sky and the lie of the land: good down to moonlight) and `seeingNear` (detail close by: needs daylight or deep twilight) on a log scale of lux; `throughAir` (Koschmieder). The numbers are judgement anchored on familiar values (full moon about 0.2 lux, clear noon tens of thousands, civil twilight's end about 3), not measurements. tests/sim/sky.mjs checks day lengths, the moon, light levels, the weather against climate and season, determinism, and the animals' seasons.

**State layers, and how systems hook onto them.** Things that change over time are kept as state that any system reads, each written by one process, so a process that changes something never has to call what follows from it. The sky (sky.js) is a pure function of the world and the hour; the ground (ground.js) is integrated day by day from the sky; the plants' seasons (phenology.js) are read off the ground; per-cell readings (water depth and speed, snow depth, leaf litter) are derived from the ground on demand. The game hangs the land as it is today on the landscape (`L.dyn`: `cross(c)`, `slow(c)`, `sound(a)`), and walking, crossing and hearing in geo.js consult it if it's there (a flood changes routes and times, a dry bed goes silent, snow slows walking, with nothing calling anything). The character's own state (`S.body`: water, reserves, sickness brewing, clothes and their wetness, a chill, a limp, a wound, skills and wear; and a bed made at a place) is changed by processes in the common shape (act.js, acts.js), including the per-tick processes in `TICKS`, each reading whatever state it declares and changing only what it declares; a new system is a new entry.

**`ground.js`** — The land as the weather leaves it, day by day: snow (snow water equivalent; snowfall adds, a degree-day melt of 3 mm per °C takes away), today's rain and melt, `soak` (an antecedent precipitation index fading 15% a day), `flow` (how full the streams run against their average: a seasonal baseflow, high in spring and low in late summer or following the rains a month behind in monsoon climates, plus quickflow from the soak), `frozen` (a week's mean below −4 °C), the growing season (`growingSeason`: the climate's mean above 6 °C, or the wet season and a month after) and `phase` through it, the deciduous canopy's `leaf` (leafing out over three weeks, falling over four) and the `litter` it drops (rotting at 0.5% a day). Run on the climate's averages for 150 days before day 1, so a game starts with the season's snow and water, then on the actual weather; the same however it's asked. Per cell: `snowCm` (more higher up, less under trees), `litterAt` (by canopy and the world's share of deciduous trees and bushes; none under snow), `waterAt` (depth and speed by stream size, steepness and flow, depth as flow^0.4 and speed as flow^0.25 after Leopold and Maddock; brooks dry below 40% of average flow, streams below 15%; ice), `crossingNow` (the hours to get over and whether the current takes me: a dry bed or ice a minute's scramble; a log or boulders standing above the water likewise; a ford spreads the water to 40% of its depth; otherwise wading time grows with depth × (1 + speed); past 0.6 m²/s of depth × speed, where people are knocked off their feet, or 1.3 m deep, the current carries me 2 to 10 cells downstream). tests/sim/ground.mjs.

**`phenology.js`** — When each plant part is there to be had: the part's own season words ("early growing season", "late growing season and the winter", "after rain", "year-round") read against the growing season's phase, with a per-species shift and fruiting length (`partNow`), and how a plant looks now (`plantNow`: in leaf, bare or died back; flowering; fruiting; how much that catches the eye).

**`body.js`** — Sleep as a process: a heat balance an hour at a time (`sleepHour`). Staying warm curled up asleep takes (33 − T) / 8 clo all told (one clo, a business suit, holds back about 6 °C at a resting person's heat output; Gagge, ISO 9920, roughly, eased for posture and tolerance). Against it: clothes (losing up to 60% of their clo soaked), the still air round me (0.7 clo, blown away by wind), shelter (a debris hut 1.5 clo with a leaf floor, keeping off 90% of the wind and 95% of the rain; trees and rocks a little of both), the ground (bare earth about −0.4 clo, worse wet or snowy; a bed of leaves, moss or dry grass puts some back), and a banked fire warming the air several degrees as it burns down. The shortfall costs sleep, burns energy shivering and builds a chill; rain on me, a roaring wind, biting insects, hunger, thirst and pain cost sleep too, each kept by name. Tuned so a mild night in the open is fair, a freezing one wretched, and a hut with a bed warm to about −5 °C.

**`injury.js`** — The risk of getting hurt on the move: a hazard rate per hour of walking, the product of the ground (steepness; scree, rock, wet clay, wading a stream bed, deadfall), the light at that cell (by day nothing extra, about ten times in a moonless night, a full moon in between; the canopy shades it), the weather (wet rock and mud, snow, fog), the body (tiredness, hunger, sickness, a limp already) and familiarity (ground walked before: half). Calibrated (judgement) to about one minor injury in 300 hours on easy familiar ground by day, about one in 40 on new ground by day over real walks, and one an hour or so on scree on a moonless night (tests/sim/injury.mjs). `injuryAt` picks what happens where: a twisted ankle or a fall on rock and slopes, a gash from a branch in thick woods, a slip into the water in a stream bed; severity lognormal.

**`smell.js`** — Smell. `windFor` gives each day's wind (a prevailing direction per world with a daily swing, and a strength). `smellSources` lists what can be smelled at a distance: carcasses of the large animals (deaths over four-day spells, density × 100 km² × days ÷ an eight-year lifespan, plus a little; each lies about four days and leaves bones), marshy lakes (about half; rotten-egg mud), a sulfur spring on volcanic ground, and the dens of the rare musk animal. `smellAt` decides what reaches the nose: full range for a source straight upwind, about a tenth downwind, scaled by wind strength, and caught three times in four. A smell gives the wind's direction and almost no distance, so smelled things go on the map as "?".

**`outlook.js`** — The start screen's indicative blurb: water in x hours (median of nine quick trial openings using the game's own perception and walking: scan, walk toward the strongest water cue, else climb to the lookout, else strike out), food in x hours (a back-of-envelope over the microhabitats within 1.5 km of the spawn: chance that a bare-handed, safe-raw food giving at least 250 net kcal per half hour, by its make-up, is at a site and is the one a beginner tries, at 1.75 h per attempt), fire in x days (the closed-form `estimateFire`). Plausible outcomes, not averages.

### Knowledge, notes and planning

**`notes.js`** — Field notes. An association ("so that's the wren") is always written after the sighting it rests on, and a link to something new brings its sighting into the note. `observeSite` decides what is present and noticed (never cryptic things; vertebrates through channels: sighting, tracks, calls, scat, damage, dens, hair), judges salience against the character's memory (running statistics of their own noisy observations), attributes animal signs (known maker, ambiguous, or unresolved sign later linked), chooses a note length (longer when several unknown things appear), and realizes text from template pools with a recency penalty. Newness commentary is held back until two consecutive visits with nothing new, and so is any expectation: until then, things met again are "again", "more of those", "the common ..." or "pretty common around here", never "the usual", "as expected" or "nothing remarkable" (tests/sim/notes-usual.mjs). `newMemory` creates the save-game memory.

**`process.js`** — The early-game process network: `MATERIALS` (raw material classes with properties), `ITEMS`, `ITEM_TRAITS` (what matters about each intermediate item), and `PROCESSES` (about 50 recipes with inputs requested by property ranges, tools with wear, durations, waiting time, attention, body load, energy, skill and base success). `materialsOf(world)` turns a world's parts into material records; `matches` / `candidatesFor` match slots; `reachable` is a forward-closure solvability check; `networkStats` gives hubs and depth; `expandGoal` builds an AND–OR goal tree; `thought` and `lookHint` render the character's one-step reasoning.

**`network-report.js`** — Renders the network document: process table, hub and depth table, reachability for a world, goal trees with candidates, and the character's thought walk.

### Crafting model

**`craft.js`** — Quality propagation, prototyped on the fire chain. `PROPERTIES` (registry with scale and how each property can be observed), `ROLES` (suitability curves over properties, with tolerance widened by skill), the generic `attempt` (latent performance score from log suitabilities, skill, effort and noise; success threshold; workmanship from the margin; learning proportional to p(1 − p)), effective skill reduced by fatigue, hand damage and focus, Archard-style edge wear, retouching that spends mass, moisture drying toward climate equilibrium, socket seating, and processes: `knapFlakes`, `searchNaturalEdge`, `splinterBone`, `notchHearth` (with an effort choice), `refineNotch`, `carveSpindle`, `makeTinder`, `handDrill` (calibrated to four anchor cases), `lightFire`. `fireQuest` runs a whole bare-hands-to-fire scenario with an edge policy; `estimateFire` is the closed-form timeline estimate used on the start screen, with one efficiency factor fitted against simulations.

### Output

**`report.js`** — Markdown game-master report: overview, starter check, microhabitats, water, minerals, plants and plant parts, animals, and patch variation with correlations.

**`tables.js`** — `toLong` (one tidy table as the source of truth), `pivotWide` (wide per-category views), `toCSV`.

**`cli.js`** — The headless commands listed above.

### The game

**`game.js`** — The playable game, built on everything above. Sections, in file order:

- *processes:* `stateFor` binds the processes' namespaces (act.js) to the game: `body` (`S.body`), `site`, `sky`, `ground`, `clock`, `mem`, `lore`, `mind`, `milestones`, `inv`, `world`, and `here`, worked out on demand from the place, sky and ground (`HERE`: the water and its pathogen score, a fire, darkness, shelter, wind, dampness, water temperature, seeing conditions, site factors, a marsh smell, the limits on seeing). Any other path names the game's state by its key (`sites`, `suspects`, `streams`, `day`, `t`, ...). `perform(proc, binding)` checks a process can be done, lets its time pass, runs it on a copy of what it declares, applies the changes, takes what it used up, adds what it made, and logs what it says; the last one is kept in `S.lastAct` (its view and outcome). Every player action is a process. The ones whose runs need the game's own helpers (the mental map, the streams, perception, the journal) are in `GAME` (poke, scan, look out, look for something, inspect and assess, test, collect, drop, name a place, think, sleep, walk): `hosted` swaps the game's state for the run's view while it runs, so those helpers read and change the copy, within the contract. They declare bundles: `TIME` (what time passing can touch: the ticks, and a collapse into sleep), `KNOW` (notes, places), `MAP` (the mental map and what I'm about). `LIVE` lists the state that is no process's business (the world and land, number-holding memos keyed by what they were worked out from, redraw counters, the screen); `MEMOS` the one memo holding the state's own things (the stream trees), private to a run.
- *helpers and setup:* typographic punctuation, state, `checkWorld` (world, landscape, spawn, estimates for the start screen), `newGame`.
- *sites:* positions on the landscape grid, microhabitat from the cell, reuse of nearby sites.
- *distant cues and suspected landmarks:* `sense` turns perceptions into suspects, with data association (merging repeated observations; "still there" means noted before this look, reported at the fused estimate's bearing) and a grouped report: water heard, water seen, landmarks, still there, calls. Modes for lookouts, scanning and focused search.
- *names for places and landmarks:* things are called what they are, with no modifier (`uniqueName`): the hill, the falls, the crossing, the cliff, the lake, the stream bank, however many there are. Proper names come two ways. I can name a place myself: rename where I stand, or, on anything collected, "Name where this came from", which names the cell it came from and keeps a marker there for good. And a stretch of stream earns a name once I've walked all of it (`nameSegments`): a stretch is an unbranched run between two of a spring or other source, a fork, a mouth or an outlet (`segmentFrom`; a stretch that runs off the edge of the land never qualifies), and it's walked once every cell of it is one I've stood in, crossed or followed along (water only noticed nearby doesn't count). It takes the name of the water it carries on from, if that has one (the stretch above a fork takes the name of the stretch below if it's the bigger branch; the stretch below a fork takes the bigger branch's), or else a new one (`newSegmentName`) from a tree or bush I know by name growing along it, else from falls on it, a spring at its head, a lake at either end, something noticed recently, or its direction from the middle of the land: "Raspberry Stream", "Lake Brook". The fork at the head of a named stretch bears its name. The journal says so ("I've walked all of this stretch now, from where it leaves the lake to the fork. I'll call it Raspberry Stream."), the stream is called by that name where it applies (`waterNameAt`), and the name is written on the map along the straight line between the stretch's ends, turned to read left to right, left off where the stretch is too short to hold it. Until then a stream is "the brook", "the stream" or "the river". A name I gave is never replaced.
- *the mental map:* `mentalMap` builds the graph: nodes are visited places (true positions), unreached suspected landmarks (believed positions; "?" when only heard once). Links between places come from `trailGraph`: every hike and every follow-the-water is remembered as legs between the places it passed (`rememberTrip` splits a walk at any known place the path comes within 2 cells, about 150 m, of, sharing out the time by each stretch's estimated time). Each suspected landmark's position is an estimate with an uncertainty (`err`, in cells: about 20% of the distance for a sighting, 45% for a sound, 60% for a smell); a new fix is blended with the old by inverse-variance weighting, so a distant glimpse doesn't spoil a close look. When a hike reaches where a landmark was thought to be, or can get no nearer, and it can't be seen or heard, it is lost (`lost`): it comes off the map until a scan or a later sighting fixes it afresh. A landmark within a step of where I stand is looked for on the spot rather than walked to. On the way to a landmark the character homes in: a fresh fix every 3 steps while it can still be seen or heard, and on reaching the believed spot it keeps going if the fix says it's further on. The walk stops the moment it arrives: for a stream, river or lake, on stepping into it or onto its shore (so I can drink), never across it; for anything else, on its cell. Lakes can't be walked through, and a cliff cell counts as eight of ordinary ground (geo.js `CLIFF_COST`), so walks skirt both: an aim inside a lake that isn't itself the destination is walked round to the shore nearest it. A tap on something I'm already at says so rather than pretending to walk. Expected times (`routeHours`, one Dijkstra field per place and state of knowledge) go round the lakes I've seen and weigh the cliffs I've seen the same way; a walk that takes twice its expected time stops with a note on how much longer it's taking and the likeliest reason. Being thirsty stops a walk at the first water only if I didn't set out from water. What I was heading for counts as found (and lends its stream to the fixes) only if I actually reached it. Things are where they are, cell by cell: every cell I stand on is its own place (never merged with the one next to it); a landmark is reached on its own cell (a stream or river on any cell of it; a lake from its shore); sight takes in everything but my own cell, so a hill next door is seen next door, and within about 120 m (the next cell) I see exactly where a thing is (`suspicionFrom`); whatever I'm standing at after looking and listening on arrival counts as reached. Each unreached landmark hangs off the place it was seen from most closely (`seenAt`, kept by `noteSeenFrom`), moving to the next-nearest place if its link would cross the map. Links are timed by what was actually walked (averaged over trips) or else guessed with `lineHours`, and predicted trip times use a walked time even when that trail isn't drawn; and marked with streams crossed on that leg or where they cut a stream as drawn. The Map tab draws it (drag to pan, pinch or scroll to zoom, a Fit button to reset; north up; filled dots for places, rings for landmarks). The links themselves (trails, shortcuts, where landmarks were seen from, with walking times along them) are hidden behind a Routes button; a scale bar under the map gives a round number of minutes walking on open ground (about 5 km/h), 60 to 160 px long at the current zoom (`scaleBar`). Tapping open map drops a pin labelled with the guessed walking time; tapping the pin hikes straight there (`go:x_y`, recorded like any hike). Two taps, so a stray touch can't start a long walk; a tap elsewhere moves the pin. Labels and markers keep one size on screen at any zoom or window size (`MAP_PX`, 15 px labels; the map re-draws when its size changes), and every marker has a finger-sized invisible tap target about 44 px across. Labels are placed by `placeLabels` (mentalmap.js), each at whichever of eight spots round its marker (right, left, the diagonals, above, below, in cartographers' usual order of preference) overlaps least with labels already placed, markers, lines and the edge of the view. They go in priority order: where I stand and the pin, then lakes and cliffs (biggest first), places I've been (most visited first), landmarks seen (most often first), landmarks only heard. Every label but where I stand and the pin is left off if even its best spot would touch a label already placed or leave the view, so a crowded map shows the important names and zooming in brings back the rest; tooltips and screen-reader labels always carry the name. Stream chevrons fall every 70 px of screen along each stream from its source down, and cliff ticks every 16 px, so flow and cliff sides read at any zoom without crowding. Under the graph lies the land itself (`landImage`), drawn with the same colours as tools/render-landscapes.py at one pixel per cell, and shown only as far as I've seen it (`markSeen`): what was in view from each place I've stood, out to about 1.5 km, by the same sightlines that decide which landmarks I see (far over open ground, little in forest, nothing behind a ridge), much further from a lookout, and the ground along the way I walked. A button switches between the land as I've seen it, the whole map (which gives the game away; for checking the generator) and none. Fit resets the view. A tap on a marker starts a hike straight there; a route is chosen by tapping the places to pass through in turn. Markers are keyboard-operable and carry their name and walking time as a label.
- *travel:* `arrive` (the walk's own line first, then what it found; `waterFound` marks the first water however it is met: arriving at it, crossing it, or spotting it within about 200 m, and only that first sighting gets "Water!"; a reached landmark lends its name to the place, noticing water within about 200 m, focused or normal arrival notes), `travelTo` (a straight journey to a landmark or known place: crossings named, landmarks passed within about 900 m added to the map, the time remembered on the edge, a note when it took much longer or shorter than expected, and, when it doesn't get there, a note with the revised direction and walking time, re-heard or re-seen if possible; being at the edge of a lake or stream counts as reaching it), `waterHere`, `waterSource`.
- *streams as I know them:* brooks, streams and rivers are lines on the map made of fixes (`S.streams`; `addFix`): cells where I've stood in, crossed, or noticed water within about 200 m, one fix per cell (a cell I already have a fix on keeps it and its stream; nothing is merged with the cell next to it), each with its flow direction (the way it runs over the next three cells), height (of the water's surface: the landscape's hollow-filled surface, which water always runs down) and size (brook, stream, river). Which stream a fix belongs to is the character's judgement (`matchStream`), not the world's identity: the same stream if within about 200 m of one of its fixes, or about the same size (within one class) and plausibly upstream or downstream of one (`flowsTo`: downhill, never shrinking, the line between them runs within 85° of both flow directions, no rise of more than 5 m above a straight descent between them, within 2.3 km); otherwise a new stream with its own name. The judgement is deliberately eager, as a person's would be, and some dotted lines are wrong; a wrong one is cut when a walk finds it dry, and a known fix is always there to aim for instead. Water only heard joins a known stream near where the sound seems to be, or starts one; reaching it attaches the fix to that stream. `streamTrees` joins each fix to the nearest fix it could flow down to (a drainage tree), re-judged from what I know each time it's drawn: no guessed link across lake I've seen, none from a fix whose way down I know (a walked stretch, or a mouth), drawn dashed with a chevron pointing downstream; a stream known at one spot is a short arrow. Noticed water is a fix, not a new place. Tapping a stream (`headForStream`) heads for its nearest point as drawn, homing and stopping on reaching water; if that point is on a guessed link and turns out dry, the link is cut (`missedStream`). Measured against the real drainage over ten seeds, 55 of 56 drawn links run where water really runs (within about 200 m).
- *following a stream:* at a stream, short white arrows (dark-edged) on the map by where I stand follow it a stage: downstream with its head at the far end, each upstream branch with a chevron at its far end pointing back downstream, like an arrow's fletching (`followOptions`, `followStream`, geo.js `followStage`): downstream, or up each branch that feeds the spot. A stage is about a quarter of an hour along the bank (no crossing time), stopping early on the cell where streams join, a waterfall or cascade, a spring, where it runs into a lake (going down) or leaves one (going up), at the source, or at the edge of the land. An arrow is offered only where a stage would reach a new place (none downstream from a mouth). The stretch walked is laid down as a fix on every cell of the water, kept in order as a run, and drawn solid, so a stream followed in stages runs unbroken from its outlet or spring to its mouth, and branches meet on the fork's own cell; water already known under a different name turns out, once walked along, to be the same stream (`mergeStreams`: the older name stays). Only fixes with no walked link downstream get guessed links. Each stream is drawn as unbroken lines from each source down, a new line wherever walked gives way to guessed. A walked stretch keeps a fix on every cell (so the topology is checked cell by cell), but its line is drawn through only the fixes that matter (forks, ends, springs, falls, mouths, outlets, places marked on the map) and one cell in ten between, as a cubic Hermite curve: through each of those fixes it runs the way the water runs there (from three cells upstream to three cells downstream as walked; for a guessed link, the flow direction seen at the fix), one direction for both sides of the point, so the line never kinks. Where the water turns sharply just at a drawn point (its direction more than 60° off the line to either neighbouring point), the point takes the direction from its neighbour before to the one after instead (as a Catmull–Rom spline does), so the curve doesn't loop. Chevrons are spaced along the curve. Follow the water, the old action, is gone (its buttons never worked).
- *lakes and cliffs:* areas and lines on the map, drawn from the cells of them I've seen (`seenPieces`): the land reveal, plus, when a lake or cliff is seen as a landmark, the cells of it in my line of sight out to 4 km (`revealFeature`; a cliff face counted as standing 8 m, so it shows where flat ground wouldn't). A lake is drawn as circles on the cells of it I've seen (`lakeShapes`), each as big as fits inside the lake's real shore there (`lakeDistance`), biggest first, a circle added for any seen cell not yet inside one, centres nudged a little (fixed per cell) so the edge looks natural, the lake faded as one shape. Sight to a lake cell aims at the water's surface, not its bed, and nothing grows on open water. Standing on a lake's shore, the lake's cells in sight from the water's edge go on the map (the trees of my own cell not in the way; no time taken and no scan); a cliff (at least three cells seen) is a line along its main axis with ticks on the low side (`cliffLine`). Each is named when first seen, in game logic (`noteSeenFeatures`): lakes by their journal names, a cliff by the name of the cliff already spotted there, if any. One name per lake or cliff, on its biggest seen piece. Its landmark ring goes once its shape is drawn. Tapping one heads for its nearest seen part (`headForFeature`): for a lake, the walk stops on the shore of it. Springs where I've been are blue dots.
- *time, weather and seasons:* the clock is the sky's (sky.js). Night is when the sun is more than 6° down (`isNight`; too dark to work), dawn and dusk when it's below 10°; sleep ends a quarter of an hour after civil dawn, so summer mornings start early and winter ones late; "Until dusk" rests until sunset. The header shows the day, time, season, weather and temperature, and the moon at night. The journal notes rain starting and stopping, fog coming and lifting, storms, nightfall (with what the moon is doing, or that cloud hides everything), and a new season on waking; the game opens with the morning's weather. Rain, fog and snow make things damper (`ambient`: what tinder and wood dry or soak towards); rain eats a fire in the open (a storm three times as fast; a hut keeps it off). How a night goes is worked out hour by hour (see *sleep*); mosquitoes and gnats bite only while it's 10 °C or warmer.
- *seeing and hearing by the light and the weather:* sight of distant things (hills, lakes, cliffs, river lines) scales with `seeingFar` and fades with distance through rain, snow or fog (`perceive`'s `sky`); hearing loses range in rain (to about half) and storms; the land revealed around me (`markSeen`) and the lakes and cliffs in sight (`revealFeature`) shrink at night and in fog. Close by, how well I can make out detail (`nearLight`: `seeingNear` of the light under the canopy here) scales noticing plants and animals and finding tracks, droppings, damage, dens and hair (notes.js `observeSite` `cond`); calls are unaffected by dark. In the dark the note says so ("Too dark to make out much"; "Too dark to see much; mostly I listened"), talks of no sun or shade, and, when it’s really dark, only of what can be felt underfoot. Scanning at night is listening. Heading for something heard and finding it's my own cell, I listen hard and step over if it's next door.
- *animals through the year and the weather (life.js `BEHAVIOUR`, `animalNow`):* each kind has a breeding season (birds in spring, or with the rains in monsoon climates; frogs in the spring rains; deer in autumn, the rut; boar in early winter; wolves and big cats in late winter), dormancy below a daily mean temperature (lizards and frogs, and every insect, worm and snail; in some worlds the rodent hibernates), migration (some worlds' songbirds and soaring birds leave below 8 °C), shyness in rain (birds go quiet and hide), calling more in rain (frogs), and needing sun (lizards bask, soaring birds ride thermals: little seen under cloud). Dormant and migrated animals aren't seen, heard or tracked; breeding animals call two and a half times as often, mostly with a call of the season (a song, a roar, a howl: `behaviour.breedCall`, made after every everyday call so those stay as they were). A call of the season is a sound of its own, so someone who knows the everyday call hears it as new ("Something calling: ...") until they see the maker calling ("so that's the elk"), by the usual rules for unattributed signs. Rain fills and blurs tracks (a third as many found). Eggs are only there while the animal is nesting.
- *sleep:* sleeping runs hour by hour to first light (`sleep`, body.js): the night's temperature, wind, rain or snow, the ground's wetness and snow, the shelter (a hut, or the trees and rocks here, less in leafless woods), a bed made here ("Make up a bed" from carried dead leaves, moss or dry grass; "Add to the bed"; it can get wet), my clothes and how wet they are, a banked fire, and my body. Each hour's quality mends tiredness, sickness, a bad ankle and sore hands; the cold burns energy shivering and builds a chill that lingers into the morning ("I woke shaking, stiff and grey with cold"; a bad one can turn into a chest chill), warmed off by moving and a fire. The morning's line names what kept me awake, at most two things: "A cold, broken night. The bare ground drew the heat out of me, and rain fell on me half the night." Clothes get wet in rain out in the open and dry with wind, sun and a fire (a tick), and wet clothes are cold ones.
- *water through the year:* the streams on the map never change; what's in them does (ground.js). A dry bed is still the stream on the map; crossing it says so ("crossed the dry bed of the stream"), arriving says so ("The brook is dry here: a bed of stones and sand"), it can't be drunk from, it makes no sound, and following it is following the dry bed. Ice ("frozen over; water moves under the ice") is easy to cross and can be broken to drink. In spate ("brown, fast and loud, well up its banks") a stream is louder, slower and riskier to cross, and walks plan for it (`routeHours` re-reckons each day). Crossings have a height (a log 0.5–1.1 m, boulders 0.3–0.7 m above the bed) and are the easy way over while the water stays below them; journal lines say how ("on a fallen log", "at the ford", "waist-deep", "running high"). Deep fast water knocks me off my feet and carries me downstream ("carried me 230 m downstream before I could claw my way out"), soaking me and everything I carry, sometimes hurting me.
- *plants, leaves and snow through the year:* leaves, flowers, fruits, seeds and mushrooms come and go with each species' season (phenology.js); Collect offers what's out of season as "not in season now" and gathers less of it early or late; herbs and grasses die back and are harder to spot out of season; flowers and fruit catch the eye. Deciduous woods go bare in winter (and in the dry season in savannas), so their shelter thins, and drop leaf litter that hides what's low down (herbs, mushrooms, stones, small creatures: half as findable under a thick layer) and tracks, and can be gathered as bedding. Snow hides everything low down and buries roots, stones and the like ("under the snow"), slows walking (knee-deep doubles the time), raises the risk of a fall, chills a night on the ground, and shows tracks (fresh snow best). Notes mention snow underfoot, thick leaves and bare branches.
- *what limits a look:* scanning, looking out or surveying in the dark, at dusk, in fog, rain, snow or a strong wind says what's limiting it ("Too dark to see far; only the skyline shows." "Rain on the leaves drowns out distant sounds."). Once a night, awake in the dark, a line on the moon, or that cloud hides it.
- *getting hurt on the way:* every walk (a hike, a stage along a stream or a shore) risks an injury (injury.js; at most one per walk, on a cell picked in proportion to its share of the risk; `onTheMove`). Every cell walked through is remembered (`S.trod`) and is safer next time. A twisted ankle limps: every walk takes up to two and a half times as long until it heals (about a tenth of its severity a day, faster with sleep); a fall skins the hands (sore hands for crafting) and tires; a gash from a branch can go bad a day or so later unless washed within a few hours ("Wash my hands" washes it too); a slip into a stream soaks everything carried. The injury line names the likeliest reasons, the biggest factors at the spot (`injuryReasons`: at most two, each adding half again or more to the risk): "Badly twisted my ankle. I can barely put weight on it. Probably because I can’t see in the dark and I’m too tired." The body panel shows the ankle and the cut until they heal.
- *crossings:* fords (wide, shallow water over gravel, on gentle ground), deadfalls (a tree down across the water, in woods) and rockfalls (boulders, on steep ground) on streams and rivers (landscape.js: about one stream or river cell in fifteen, never two within five cells; `L.crossing`). Getting over the water there takes about a minute instead of about five (geo.js `crossHours`), so routes use them. A crossing is noticed when I pass within a cell of it (`noticeCrossings`: "A way over without wading: a tree down across the water. Marked the crossing."), and drawn as a pair of short bars across the water, labelled "crossing"; tapping it heads there.
- *where I crossed:* a stream crossed on a walk is a fix on it, joined to the rest of the stream only by a guess until I walk along the stream through that cell; until then it keeps a small open circle of its own on the map ("where I crossed"; tap to go back there), which goes once the crossing lies on a walked stretch.
- *walking a lake's shore:* on a shore, two white arrows by me walk it a stage either way round, the water on my left or my right (`shoreOptions`, `walkShore`, geo.js `shoreStage`): from one shore cell (dry ground sharing an edge with the lake) to the next, keeping the water on that side and hugging the shore, back over a cell only out of a dead end (a spit of land). A stage is about a quarter of an hour, stopping early where a stream runs in (a mouth) or leaves (an outlet), all the way round, or at the edge of the land; each of those is a place marked on the map. From every other cell of the way, the lake in sight from the water's edge goes on the map. Over eight worlds, walking round in stages reaches every shore cell of almost every lake.
- *places worth a marker:* every cell I've stood on is a place (the game remembers what I found there), but once I've left it, it's drawn only if it's of interest on that cell (`unmarked`): a landmark I reached there, a stream's mouth (where it runs into a lake) or outlet (where it leaves one), a fork, a spring, a waterfall, a crossing (`waterMark`), a lookout, a clay bank, where I woke, a hut or a fire, or a name I gave it (gathering somewhere no longer keeps a marker by itself: naming where an item came from does). Anything else is marked only while I stand on it. New places at a mouth, outlet, fork, waterfall, spring or crossing are named for it, and keep that name when a landmark is also reached there. Water noticed nearby is shown where it is (a stream fix, or the lake's cells in view), never as a place I haven't stood on.
- *time, needs, body:* `pass` advances time (thirst, hunger reserves of about ten days, drying, delayed sickness, day rollover), `collapse`, `sleep` (quality from shelter, banked fire, cold), `restOptions` / `restFor` (rest for an hour, two hours, until dusk, or until morning; short rests recover fatigue, sore hands and focus in proportion to the hours), `bodyWords` (state shown only as words).
- *items:* the pack, impressions from glance properties plus tests, food memory keyed by perceived identity.
- *gathering:* `gatherOptions` lists what can be collected from noticed things, by part and species. Roots and tubers need a digging stick, except by hand in soft ground at the water's edge.
- *looking for something in particular:* the Look action takes a useful category (spindle wood, hearth-board wood, stone for edges, naturally sharp stone, tinder, fibre, food, bones, game sign), any thing already known by name, or something in the distance (water, high ground). `lookAt` runs the matching action: a focused survey for visible things, a focused poke for cryptic ones (stronger than a general poke), a focused scan for the distance. It runs in full where I stand (half an hour) and on arrival, and `lookAlong` glances at each patch passed on the way (about every 500 m), making a place of any patch where something turns up. Travel is 25% slower while looking. The button reads "Looking for … (✕)" until pressed again.
- *smell:* `associateSmell` turns a smell into a suspect placed upwind at a very rough distance (a marsh smell is the lake it comes from); arrival and scans report "On the wind from the west: …". `localSmells` adds a "smells:" line to a survey (resin, onion, mint, ripe fruit, mushroomy earth, bees, droppings by the flies, a predator's marking, stagnant water). Reaching a smelled carcass finds bones. The wind is shown under How I feel.
- *eggs:* ground birds, songbirds and lizards lay eggs that can be eaten (life.js `EGGS`; food.js spec `egg`: about three-quarters water, 10% fat, 13% protein; raw egg white only half digestible, more once cooked; germs on the shell that cooking kills). Where one of them has been noticed in its own habitat, Collect offers its clutch ("a clutch in a scrape on the ground", "a few small eggs in a cup nest", "a clutch of leathery eggs under a stone"), once per place: about 250 g from a ground bird, 30 g from a songbird, 20 g from a lizard. They're in the world's food tables (part "eggs": where found, raw, cooked, make-up).
- *insects:* flies, mosquitoes and gnats (no food; biters near water spoil sleep unless a banked fire smokes them off), wasps, and bees. A hive is found by poking around in woodland or deadfall, or by looking for bees; its honeycomb is about 900 kcal for half an hour's raid. Raiding any stinging insect without a fire here means stings (sore hands, a little sickness).
- *food:* a food item carries its make-up and mass. Pound (a stone), Grind (two stones; seeds, nuts, dried roots), Roast in the coals (quick, which may char, or slow), Leach in the stream (2, 8 or 16 hours; needs running water), Soak in still water, and Dry (sun or fire) each apply an exposure, change the weight with the water, clear old test results, and add to the name ("nuts to eat, pine (pounded, leached 8 h)"). Smell, staged taste and bite-and-chew read the current state, so tasting between leaching sessions shows the bitterness going. Eating roasts first if a fire is here, eats only what the gut holds (about 1.5 kg, clearing over half a day), and digests: harm sets the old outcome bands; parasites can bring a fever later; energy is net of digestion, so a food can cost more than it gives; protein beyond about 35% of the last day's energy is wasted and sickening (rabbit starvation), and the Body tab says when I crave fat or starch. Pound uses the pounding stone's hardness and weight; Grind the grittiest stone carried; Chop needs an edge; Leach and Soak use the water's temperature (springs at the mean annual temperature, streams a little colder, still water warmer). A toggle under How I feel shows the exact properties of everything carried.
- *germs:* every item carries a germ load (0–1), set at gathering by what it is (soil on dug roots and creatures' guts high, fruit and nuts low), and so do the hands. Whatever is handled together mixes toward a common level (`touch`): gathering, every preparation, eating, and slowly, carrying things together. Moist food breeds germs over time, faster in warmth; drying stops it, and spoiled food smells off. Roasting, stone-boiling, fire-hardening and scorching a tool in the flames kill them; washing an item or my hands in the water helps but leaves the water's own germs behind. Eating germs risks a sour gut later, from the food and, less, from my hands. Lye comes later.
- *cooking basins:* a rock hollow (outcrops, stream beds, scree, banks; found or not) or a clay-lined pit (clay banks), made where there is water and fixed to that place. Stone-boiling heats the stones carried in the fire and drops them in: three or more bring it to a boil, fewer only simmer, and stones crack according to their spall risk.
- *poking around:* `pokeAround` turns stones and logs, peels bark and prods the litter for half an hour. It is the only way to find cryptic things (grubs, beetles, worms, woodlice, crickets, snails, crayfish, litter mushrooms), and it also turns up the visible small creatures. Each candidate is found with probability 1 − exp(−reach × abundance / 25) (/10 for mushrooms), where reach is 1 bare-handed or 1 + 1.5 × hardness with a digging stick; poking blunts a soft stick faster than a hard one.
- *digging stick:* made from a green shoot or dead wood with an edge (½ h) or by grinding on rough stone (1 h). Hardness ≈ wood density × (0.75 + 0.25 × finish), less if green. Fire-hardening (needs a fire; quick or careful) adds 18% or 30% of the remaining headroom, less on later passes, and hurrying chars the tip a third of the time. A thumbnail test reads hardness in words.
- *survey and focused search:* `presentAt` (shared abundance logic), `survey` (counts sorted by abundance, short descriptions for unnamed things, animal sign), `FOCI` (what each search focus matches by visible features, best-bet ranking, makeshift fallbacks, nearest suitable place), `focusedSearch`, `breakthroughs`.
- *inspect and assess:* close description; the character's educated guess at uses, risks and informative tests (costs focus).
- *picker:* the collect, inspect, assess, search and explore pickers.
- *tests and crafting:* `testsFor`, `RECIPES`, `pickSlot` (defaults use only visible properties), `craft`, `drill` with `drillTrouble` (names the largest penalty in the performance model), `ember`.
- *bones:* `boneFinds` draws bones per vertebrate as a Poisson count with mean ∝ density × body mass × visibility of the ground. The reasoning: finds ∝ density ÷ lifespan × persistence × visibility, with lifespan ~ mass^0.25, visibility ~ mass^(1/3) and persistence taken as ~ mass^1 (small carcasses are scavenged in days, large long bones weather for years), so the exponents sum to about one and bone supply tracks standing biomass. Birds' hollow bones and anything under 3 kg give fine bones (needles, awls); larger animals give big long bones (handles, splinters). Bones turn up incidentally in a survey (about a third of the rate), deliberately with Search or an Explore focus, and once noticed can be collected.
- *actions, eating, plans:* `hereActions` (Survey, Look, Poke, Scan, Make, Inspect, Collect, Drink, each with a subtitle; then, where they apply, Look out, Feed the fire, Build a debris hut, Rest). Inspect also assesses. `doHere`, `eat`, the goal tree rooted at any item or process with focus costs.
- *the game record:* every player action is the data of what was tapped (or the value chosen), applied by `act` and appended to `S.record` with the day and time. "Copy game record" under How I feel gives `{ game, version, build, seed, preset, actions }`; pasting it under "Replay a game record" on the start screen rebuilds the world and replays every action, reproducing the game exactly on the same build (a different build is flagged). This is the back-end log for bug reports.
- *the map as data:* `mapData` gives what the map shows (places and landmarks with their marks, links, streams as the lines drawn and the fixes each is drawn through (`streamLines`), lakes, cliffs, crossings, where I crossed, follow and shore arrows, the pin, and every target a tap can head for, in the map's order); `mapHTML` draws from the same pieces. `stepGrid` keeps each day's step times for route-finding (`routeField`).
- *rendering and events:* incremental journal rendering (a five-line scrolling log at the bottom of the screen; after each action the first entry it wrote is scrolled to the top of the log), panels, mobile tabs (Actions, Carry, Plans, Body), click and change handlers, start screen.
- A debug hook, `window.__hk`, exposes state for automated tests only.

**`shell.html`** — The page: design tokens for light and dark mode (cave-pigment palette), Newsreader for the journal and Archivo for controls, the log strip at the bottom of the screen, a rule that the hidden attribute always hides (the start screen used to stay visible behind the game), a New world button under How I feel that returns to the start screen, the three-column desktop layout (body and plans, actions, carrying) and the mobile tab bar, and a placeholder where the bundle is inlined.

## Tests and analyses

### Run times

`tools/timed.mjs` runs a batch of commands, prints a `⏱` line with the time after each, and ends with a summary of every step, the batch's wall-clock total and, when steps ran side by side, the sum of the steps' own times (the machine time spent); it stops starting new commands at the first failure and exits non-zero. With `-j N` up to N commands run at once (their output held and printed whole as each finishes); `::` between commands is a barrier (the build before the tests). Each batch is appended to `out/timings.jsonl` (date, label, jobs, steps, total, summed, pass/fail), so run times can be compared across changes and added up over a round of work. `npm run t -- "<command>" ...` runs any commands as a batch labelled `debug`, so one-off runs while debugging are logged too.

    node tools/timed.mjs <label> [-j N] -- "<command>" ["<command>" ...] [:: "<command>" ...]

The npm scripts use it, four at a time (the sandbox has four cores). Where the time went, and what was done about it:
- *Drawing after every tapped action* was half of a map-heavy UI test. Tests that are about the game rather than the picture now play without drawing (`tests/ui/drive.cjs`: the page is opened with drawing off, actions go through `__hk.act`, and the state, the journal and the map are read as data through `__hk.mapData`, `__hk.journal`, `__hk.actions`); they draw once (`__hk.draw()`) only to check the drawing itself (labels in features.cjs). names.cjs and reported.cjs, which check labels, marker positions and the curves' kinks, still read the drawing, after replays that draw once.
- *Travel times for the map's labels* were a whole-map route search after every move or scan. Each day's step times are now worked out once into a grid (`stepGrid`), and the search runs over that with a typed-array heap; this speeds up the game's map for players too.
- *Making the same worlds again in every test* was about a quarter. Made worlds (species, landscape, spawn) are kept in `out/cache/worlds` by `tests/ui/page.cjs`, keyed by seed, preset and a hash of the code that makes worlds (computed by `build.mjs`), so a changed generator never reuses an old world; and a test page no longer makes a random world for the start screen on opening.
- *Running tests one at a time* on a four-core machine: the tiers now run four at once.

## The simulated player method

Automated play was the main way of finding problems that unit-level checks miss. Three tiers were used:

1. **Random agent (`smoke.cjs`).** Clicks any enabled button, weighted toward a priority list, occasionally changing select boxes. It finds crashes, dead ends and impossible states (for example the clock reading 30:29, or recursion errors), not balance problems.

2. **Rule-based player (`scripted-player.cjs`).** Plays like a sensible beginner. Its key constraint is that **it sees only what a human sees**: journal text, body words, item names and impressions, and button labels. It acts only by clicking buttons and changing selects. It never reads hidden state to decide anything. Each step follows a priority list: rest until morning at night; when thirsty, drink, return to known water, follow water cues, look out, or head for a hill; when very hungry, eat food not remembered as sickening, or gather calorie-dense food; rest the hands with light work; otherwise pursue the fire plan (gather and test-break stones, knap with the best core and a different hammer, or else collect or search for a big bone and smash it; gather and thumbnail-test dead wood, notch the lightest carefully; trim or carve spindles; make tinder; keep spare wood; snap-test spindles, choose a dry straight one, touch up a ragged notch, drill). A stall detector stops it when nothing changes.

   Because it sees only the UI, every failure is either a game problem or a strategy problem, and telling the two apart is the point. During development it exposed real game bugs (food and tinder sharing one button label, slot defaults that leaked hidden quality, a notch quality that could reach zero, the journal re-rendering on every click) as well as many bugs in its own logic.

3. **Hidden-state inspection, for diagnosis only.** When the player stalls, the debug hook (`window.__hk`) is read *after* the run to compute the true suitability of the items being used. That is how the zero-notch bug and the crooked-spindle default were found. Decisions never use it.

A rule-based player is a weak player. It notches whatever dead wood is nearest rather than seeking better wood, so it is slower than a thoughtful human and sometimes fails where a person would succeed. Its results are a lower bound on what good play achieves.

## Known limitations

- **The game-side processes declare coarsely.** Walking, sleeping, looking and scanning run the game's own helpers on a view of the state, and declare it in bundles (all places, the whole mental map, the whole body), so their stated inputs are broader than what they use; what they changed (the diff) is exact. Their contracts are checked only when they run, so a branch no test reaches could still read something undeclared. Setting up a new game (the first look round) and choices on screen (the goal, slot picks, the map) aren't processes. A walk runs its steps (`WALK_STEP`) directly rather than through `rehearse`, for speed; any step can be run again from `stepView`.
- **The closed-form fire estimate predates the geography.** It picks materials from species lists, not from what is near the spawn, so the start screen's fire day can be optimistic for a particular spawn. Rewiring it to sample around the spawn on the landscape is the fix.
- **Microhabitat shares from the landscape differ from the environment's frequency estimates** used to place species, so some species may be rarer or commoner on the ground than their tables imply.
- **Early starts are a hungry gap.** Games start between late March and mid-August; with plants in season only in season (phenology.js), most of the calorie-dense food (fruit, nuts, seeds) isn't ripe yet, and the start screen says "little food to be had" in about two worlds in three (tests/sim/outlook.mjs). The scripted player, which only looks for food where it stands, starves into a loop of collapses, so its soak run now covers hundreds of days and takes a couple of minutes. A later start window, or a smarter forager, would change that.
- **The outlook ignores the weather.** Its water trials and fire estimate assume a clear day (its food estimate does take the season into account); a beginner sleeping out on cold nights tires and loses days, and rain keeps wood damp. Folding the sky into the trial openings is the fix.
- **Hunting and trapping are not built yet.** The animals' state (`animalNow`: about or not, breeding, shy in rain, how often seen and heard) is there for them to read; the processes are to come.
- **Daytime rests aren't the sleep process.** Resting for an hour or until dusk recovers on the old fixed rates; only a night's sleep runs the heat balance.
- **The ground is one column.** Snow, soak and flow are for the land as a whole (snow scaled by height and canopy per cell); no rain shadows, no upstream catchments routing a storm down a river a day later, no lake levels.
- **The sky is judgement, not climatology.** One hemisphere, solar time, no topographic shading of the sun, no snow cover on the ground, no rain shadow or valley fog, a moon without its 5° tilt or libration; the weather chain is the same shape in every climate, scaled.
- **The outlook's food estimate is generous.** It ignores season, detection during a survey and the time taken to judge a food safe; tuning it against the scripted player is the fix. The panorama's constants (blur width, masking, the falls/cascade threshold and ranges) are judgment, not measurement.
- **Moss and fine bones have no use yet.** Both can be gathered and carried; bedding, dressings, needles and awls are not craftable.
- **Animals have no positions.** Calls heard during a scan get a random direction and are not explore targets.
- **Only the fire chain is craftable in the game.** Cordage, containers, cooking and shelter beyond the debris hut exist in the process network and the planning tree but not as game actions.
- **No saving.** Seeds reproduce worlds, but a game in progress is lost when the page closes.
- **Sight and sound ranges, density tables and most constants are hand-tuned placeholders.** The structure follows published ideas (cited in comments); the numbers are not empirical fits.
- **`src/GENERATOR-NOTES.md`** is the generator README from earlier development. Some command examples there (for example `walk`) describe the pre-geography notes engine.
